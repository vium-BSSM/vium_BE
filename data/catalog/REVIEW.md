# 재료 카탈로그 초안 검토 — #87 2단계

이 단계는 입력 데이터 초안이다. 소비기한 일수·manual 규칙·V9 SQL은 아직 생성하지 않았다.

## 구성

- `ingredients.csv`: 411개. 이름은 대표 표기 하나를 사용하며 가공 상태가 다른 품목은 구분한다(마늘/깐마늘/다진마늘, 우유/멸균우유 등).
- `match_samples.csv`: 150개. 기존 OCR 픽스처의 상품명과 추가로 작성한 합성 사례다. 실제 영수증 150건에서 수집한 데이터가 아니다.
- FoodKeeper ID 지정: 271개. 원본에 없는 ID를 임의 생성하지 않았다. `note`에 원본 이름·부제를 기록했다.
- FoodKeeper ID 미지정: 140개. 이름·상태가 직접 대응하지 않으면 비슷한 품목으로 대신 연결하지 않았다. I1250 또는 4단계 manual 검토가 필요하다.
- I1250 유형: 두부·어묵, 냉장. 두부는 FoodKeeper와 중복 출처이며 I1250 우선이다. 다른 한국 가공식품은 정확한 유형과 보관조건 확인 전 매핑을 비워 두었다.

## 검토할 결정

- 기본 단위는 구매 시 흔히 쓰는 단위로 정했다. 채소·육류·수산물은 g, 개별 과일은 ea, 포장 식품은 pack/bag, 액체는 ml 또는 bottle을 사용한다. 포장 단위와 중량을 자동 환산한다는 뜻은 아니다.
- 계란은 기존 카테고리에 알류가 없어 기타에 배치했다. 별칭용 `달걀`, `대란`, `특란` 항목은 추가하지 않았다.
- 가공 음식·브랜드 상품은 카탈로그에서 제외했다. 매칭 샘플의 김밥·찌개·과자·비누는 잘못 연결되지 않아야 하는 음성 사례다.
- 돼지 부위명은 계획의 짧은 이름을 따른다. `돼지고기앞다리살`은 현재 방식에서 일반 `돼지고기`로 매칭되므로 별칭 개선 대상이다.
- 감자·통양파 등은 냉장 규칙이 있으면 스캔이 냉장을 먼저 고른다. 4단계에서 실온 우선 여부와 제외 규칙을 검토해야 한다.
- 냉동 품목은 원본의 냉동 판매 항목에만 연결했다. 3~4단계에서 frozen 규칙만 남는지 확인해야 한다.
- FoodKeeper ID가 있다는 것만으로 모든 보관방법의 유효 일수가 확보되는 것은 아니다. 우유의 냉장 값처럼 포장 표시일을 따르는 항목은 자동 일수를 만들지 않는다.
- I1250의 제조일 기준 기간을 구매일 기준 추정에 쓰는 한계, 개봉·손질 상태와 보관 온도의 차이는 일수 검토 때 고려해야 한다. 이 초안은 식품 안전성을 보증하는 표가 아니다.

## 매칭 점검

`PurchaseScanService`의 공백 제거·소문자화·긴 이름 우선·한 글자 토큰 일치를 임시 점검으로 재현했다. 동률은 CSV 순서(빈 DB에 삽입했을 때의 ID 순서)로 가정했다. 기존 DB의 ID 순서가 다르면 동률 결과는 달라질 수 있다. 정식 점검 함수는 3단계에서 구현한다.

150건 중 134건 일치, 16건 불일치다. `expected`는 현재 알고리즘의 결과가 아니라 사람이 기대하는 재료다. 불일치를 없애려고 기대값을 현재 결과로 바꾸지 않았다.
